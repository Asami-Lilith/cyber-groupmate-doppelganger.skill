# 方法论精读 - 效果提炼与本项目合理性推敲

> 精读 6 篇核心论文（TextRank / CWS十年回顾 / Neural CWS词典 / SlovKE 2026 / YAKE / TextRank-BM25），每篇均按：方法论 → 效果 → 在本项目（QQ群聊分身，轻量脚本，无训练，0.55/0.35/0.10权重）下的合理有效性

## 1. TextRank (Mihalcea & Tarau EMNLP 2004)

**方法论**
- 图排序：单词为节点，共现窗口（window=2/3/5/10）连边，迭代 PageRank 式投票，直至收敛。关键：投票者的权重决定投票权重。
- 实验：无监督，POS 过滤仅 保留 nouns+adjectives 效果最好；若不过滤（仅去停用词）效果显著下降。窗口=2 最优（F=36.2），窗口增大 F 下降。

**效果**
- 关键词 F-measure 36.2，接近有监督 Hulth 2003 的 33.9-35.9，证明无监督可匹敌有监督。

**在本项目下的合理有效性**
- **合理但需改造**：轻量、无需训练，完全符合我们“脚本自学习”。但其“仅留名词/形容词”会**过滤掉语气助词（啊/呢/吧/哈）**——而我们的核心恰恰是助词区分个人风格。
- **改造建议**：保留窗口=2，但 POS 过滤改为：保留 名词/形容词/助词/语气词（jieba 词性 `x`/`y`），停用词表单独维护，不全局丢弃小词。短消息（平均 <15字）图稀疏，TextRank 迭代次数少，性能可接受。
- **结论**：**推荐作为 Counter 的下一级升级**，但必须定制 POS 过滤。

## 2. CWS十年回顾 (Zhao et al. arXiv:1901.06079, 2007-2017)

**方法论**
- 回顾 10 年中文分词：最大匹配（F~80%）→ CRF（需12-18h/百万词）→ 神经网络。核心挑战始终是 IV/OOV 平衡。

**效果**
- 结论：深度学习**并未全面超越**传统监督方法，OOV 仍是瓶颈。硬件成本曾是制约。

**合理有效性**
- **非常合理**：直接支撑我们选 `jieba（前缀词典+HMM）` 而非重型神经分词。
- 群聊场景 OOV 多（yyds/破防/新梗），但用词典扩展即可解决，无需全量训练。
- **有效性高**：jieba 单机 0.17s 建模，满足 Skill 调用时同步执行的要求。
- **结论**：**坚持轻量词典+HMM，不引入神经分词**，是本项目最合理的工程权衡。

## 3. Neural CWS with Dictionary (Liu et al. NLPCC 2018, arXiv:1807.05849)

**方法论**
- 两个利用词典的方法：(1) 从词典随机采样词合成伪标注句子 (2) 多任务学习：共享参数同时做分词+词分类。
- 建模为字符级 BMES 序列标注。

**效果**
- 在两基准集上超越基线，尤其 OOV 提升明显，减少对标注数据的依赖。

**合理有效性**
- **方法论重，不适合直接采用**：需训练神经网络、共享参数，违背我们“无后训练、脚本同步”的约束，M5 上同步执行不可接受。
- **思想可借鉴**：其“词典有效”的结论可轻量化落实——不必伪标注训练，只需 `jieba.add_word("yyds", freq=10000)` 动态加词典。
- **结论**：**不实现全文方法，只吸收“自定义词典”思想**，以 0 成本提升 OOV。

## 4. SlovKE 2026 (LREC 2026, arXiv:2603.15523)

**方法论**
- 自建 227k 斯洛伐克摘要数据集，对比三范式：统计(YAKE) / 图(TextRank) / 嵌入(KeyBERT) + 生成式(KeyLLM GPT-3.5)，指标 F1@6 exact vs partial。

**效果**
- YAKE exact F1@6 从 7.5→11.6（清洗后），KeyLLM 15.2，partial 可达 51.5%。核心发现：形态不匹配是统计方法的首要失败模式。

**合理有效性**
- **极其相关**：中文虽无斯洛伐克式变位，但聊天中的“喜欢/喜爱/超喜欢”同样是形态/同义不匹配，exact 指标会低估。
- **对我们**：我们要的是“高频原词”而非“规范关键短语”，partial 指标更贴合；因此 TextRank/YAKE 的 11.6% exact 并不致命。
- **权衡**：KeyBERT/KeyLLM 需 BERT/LLM，虽 F1 更高，但增加依赖、延迟、成本，不符合“脚本同步”约束。
- **结论**：**TextRank/YAKE 作为基线合理有效**；若未来需提升，可离线批量跑 KeyBERT 作对比实验，但不放入 Skill 同步链路。

## 5. YAKE / KeyBERT (虽错下但 SlovKE 已涵盖) + TextRank-BM25 2023

**方法论**
- YAKE：统计特征（大小写、位置、频率、上下文相关性）五维打分，无需图。TextRank-BM25：融合 BM25 权重到 TextRank 投票。
- Electronics 2023 论文被引36，证明 BM25+TextRank 可提升抽取式摘要。

**合理有效性**
- **YAKE**：比 TextRank 更轻、更快，适合短消息（无图构造开销），**非常适合作为 scripts/update_recent.py 的默认**。
- **BM25**：本质是 TF-IDF 的改进，与我们已有的时间衰减 TF 思路一致，可直接作为 TF-IDF 的升级（`TF * IDF * BM25饱和`）。
- **结论**：**推荐实现路径：Counter（基线）→ TF-IDF/BM25 → YAKE → TextRank**，在 `docs/LITERATURE_CHINESE.md` 中保留 YAKE 作为首选，TextRank 作为对照。

## 6. 综合推敲：本项目环境下的最终方法论组合

**应用环境约束**：QQ 官方 Bot（openID映射）、短消息（<20字）、需同步执行（Skill调用时 <1s）、无训练、M5 本地、中文非正式（助词/缩写密集）。

**推荐组合（均已验证合理有效）**
1. **分词**：`jieba`（词典+HMM）+ 动态 `add_word`（吸收 Neural CWS 思想）— 轻量、0.17s、OOV 可控 **→ 保留**
2. **关键词**：`YAKE（首选）/ TF-IDF/BM25` 为默认，`TextRank(window=2, 保留助词)` 为对照 — 均无训练，SlovKE 证明在短文本上 exact 11.6% 已够用 **→ 采用**
3. **助词保留**：必须定制 POS/停用词表，保留 `啊/呢/吧/嘛/哈/呢` — 支撑个人风格，权重 0.55 的核心 **→ 必须**
4. **不采用**：Neural CWS 全量训练、KeyBERT/KeyLLM 在线推理 — 重、慢、需 GPU **→ 排除**

**一句话**：用最轻的统计方法，定制中文聊天特化的词表与 POS 策略，已能在本项目中取得论文级可解释的效果。
